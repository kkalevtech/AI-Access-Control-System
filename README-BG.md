# AI Система за Контрол на Достъпа — Поведенчески Анализ

Интелигентна система за контрол на достъпа, която наблюдава и анализира опитите за достъп на потребители чрез машинно обучение. Системата проследява кой влиза, кога влиза и къде отива, след което класифицира всеки опит като **Нормален** или **Подозрителен** въз основа на научени поведенчески модели.

Създадена като **училищен проект** за 11. клас по Програмиране с Изкуствен Интелект — целият код е образователен, лесен за обяснение и реализира задължителните принципи на ООП.

# Преглед на архитектурата

Системата следва слоеста архитектура с ясно разделение на отговорностите:

```text
┌──────────────────────────────────────────────┐
│                 Flask GUI                    │
│       (templates/, static/, app.py)          │
├──────────────────────────────────────────────┤
│                Контролери                    │
│   ┌─────────────────┐ ┌──────────────────┐   │
│   │ AccessController │ │ SecurityManager │   │
│   └────────┬────────┘ └────────┬─────────┘   │
├────────────┼───────────────────┼──────────────┤
│            ▼                   ▼             │
│   ┌──────────────────────────────────────┐   │
│   │          EventDispatcher             │   │
│   │ (Observer Pattern — 3 типа събития)  │   │
│   └──────────────────────────────────────┘   │
├────────────┬───────────────────┬──────────────┤
│            ▼                   ▼             │
│   ┌────────────────┐  ┌──────────────────┐   │
│   │BehaviorAnalyzer│  │DatabaseManager   │   │
│   │    (AI/ML)     │  │ (SQLite CRUD)    │   │
│   └────────────────┘  └──────────────────┘   │
├──────────────────────────────────────────────┤
│   ┌────────────────┐  ┌──────────────────┐   │
│   │ FileManager    │  │      Models      │   │
│   │(JSON/CSV/Log)  │  │User/AccessLog/   │   │
│   │                │  │Dept/Room         │   │
│   └────────────────┘  └──────────────────┘   │
└──────────────────────────────────────────────┘
```

### Поток на комуникация между обектите

1. Потребителят подава заявка за достъп чрез уеб формуляр.
2. `AccessController` получава заявката и извлича данни за потребителя чрез `DatabaseManager`.
3. `BehaviorAnalyzer` извлича характеристиките (features) и изпълнява ML предсказване.
4. Ако поведението е подозрително, `EventDispatcher` генерира събития → `SecurityManager` ги обработва и записва.
5. Резултатът се връща към GUI заедно с нива на увереност и обяснение.

# 5. BehaviorAnalyzer

**Файл:** `src/ai/analyzer.py`

AI/ML компонентът, който класифицира поведението при достъп като **Нормално** или **Подозрително**, използвайки **Random Forest Classifier** от scikit-learn.

## Атрибути

| Атрибут      | Тип                      | Стойност по подразбиране            | Описание                                                   |
| ------------ | ------------------------ | ----------------------------------- | ---------------------------------------------------------- |
| `database`   | `DatabaseManager`        | задължителен                        | Референция към базата данни за извличане на характеристики |
| `model`      | `RandomForestClassifier` | `random_state=42, n_estimators=100` | Обучен sklearn модел                                       |
| `is_trained` | `bool`                   | `False`                             | Дали моделът е обучен                                      |

## Методи

| Метод                                                                          | Връща   | Описание                                                          |
| ------------------------------------------------------------------------------ | ------- | ----------------------------------------------------------------- |
| `extract_features(user_id, access_time, location, is_weekend, reference_time)` | `dict`  | Изгражда вектор от характеристики чрез заявки към базата данни    |
| `analyze(user_id, access_time, location, is_weekend)`                          | `dict`  | Изпълнява предсказване и връща класификация + увереност + причини |
| `train_from_database()`                                                        | `dict`  | Обучава модела върху всички данни от `access_logs`                |
| `retrain()`                                                                    | `dict`  | Псевдоним на `train_from_database()`                              |
| `save_model(filepath)`                                                         | `bool`  | Записва модела на диск чрез pickle                                |
| `load_model(filepath)`                                                         | `bool`  | Зарежда модела от pickle файл                                     |
| `get_prediction_confidence(features)`                                          | `dict`  | Връща вероятностите на модела                                     |
| `get_access_frequency(user_id, time_window_minutes, reference_time)`           | `int`   | Брои опитите в зададен времеви прозорец                           |
| `get_historical_denied_count(user_id)`                                         | `int`   | Брои всички отказани опити на потребителя                         |
| `is_assigned_room(user_id, location)`                                          | `bool`  | Проверява дали локацията съвпада с назначеното помещение          |
| `is_night_access(hour)`                                                        | `bool`  | `True`, ако часът е ≥ 22 или < 6                                  |
| `get_user_location_grant_rate(user_id, location)`                              | `float` | Съотношение между разрешени и общи опити на дадена локация        |

## Етикетиране (за обучение)

| Етикет | Значение     | Критерий                               |
| ------ | ------------ | -------------------------------------- |
| 0      | Нормален     | По подразбиране (`status = "granted"`) |
| 1      | Подозрителен | `status = "denied"`                    |

**Забележка:** За разлика от първоначалния проектен документ, етикетирането използва реалното поле `status` от `access_logs`, вместо предварително зададени правила. Това означава, че моделът научава реалните модели, присъстващи в началните данни.

---

## Детайли за модела

* **Алгоритъм:** `RandomForestClassifier` (не DecisionTree, както е било първоначално планирано)

  * `n_estimators=100` — 100 дървета на решенията в ансамбъла
  * `random_state=42` — детерминирано обучение

* **Разделяне Train/Test:** 80/20 с `random_state=42`, стратифицирано

* **Cross-validation:** 5-кратна кръстосана валидация, включена в резултатите от обучението

* **Данни за обучение:** всички записи от `access_logs`, като са необходими поне 30 записа

# 6. AccessController

**Файл:** `src/controllers/access_controller.py`

Обработва заявки за достъп и взема решения за разрешаване или отказ, като интегрира AI анализа.

## Атрибути

| Атрибут            | Тип                | Описание                                    |
| ------------------ | ------------------ | ------------------------------------------- |
| `database`         | `DatabaseManager`  | База данни за потребители и логове          |
| `event_dispatcher` | `EventDispatcher`  | Система за събития за изпращане на известия |
| `analyzer`         | `BehaviorAnalyzer` | AI двигател за анализ                       |

---

## Методи

| Метод                                                                              | Връща  | Описание                                                                     |
| ---------------------------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------- |
| `request_access(user_id, location, access_time)`                                   | `dict` | Основна входна точка — изпълнява AI анализ, генерира събития и връща решение |
| `grant_access(user_id, location, access_time, is_weekend)`                         | `dict` | Записва разрешен достъп в базата                                             |
| `deny_access(user_id, location, reason, access_time, is_weekend)`                  | `dict` | Записва отказан достъп и генерира събитие `on_access_denied`                 |
| `grant_access_with_analysis(user_id, location, access_time, analysis, is_weekend)` | `dict` | Разрешава достъп с метаданни от AI анализа                                   |

---

## Поток на вземане на решения

```text
request_access()
  ├── Потребителят не съществува?
  │      └── return {granted: False}
  │
  ├── AI моделът обучен ли е?
  │   │
  │   ├── Да → analyzer.analyze()
  │   │       │
  │   │       ├── Подозрително?
  │   │       │      └── dispatch on_suspicious_behavior
  │   │       │          + on_access_denied
  │   │       │          → return {granted: False}
  │   │       │
  │   │       └── Нормално?
  │   │              └── return {granted: True}
  │   │
  │   └── Не → _process_request() (резервни правила)
  │
  └── _process_request() резервна логика:
          ├── Съвпада с назначеното помещение? → разреши
          ├── Съвпада с отдела? → разреши
          └── Иначе → отказ + on_access_denied
```

# AI/ML Модел

## Процес на обучение (Training Pipeline)

```text
1. Извличане на всички access_logs от базата данни
         │
2. За всеки лог се извлича вектор от характеристики:
   ┌─────────────────────────────────────┐
   │ hour, minute, is_weekend,           │
   │ access_count_last_hour,             │
   │ user_access_level,                  │
   │ historical_denied_count,            │
   │ is_night_access,                    │
   │ user_location_grant_rate            │
   └─────────────────────────────────────┘
         │
3. Етикетиране:
   1 ако status='denied', иначе 0
         │
4. Обучение на RandomForestClassifier
   - 100 дървета
   - random_state=42
   - 80/20 train/test разделяне
   - 5-fold cross-validation
         │
5. Моделът е готов за предсказвания
```

---

## Процес на предсказване (Runtime)

```text
Нова заявка за достъп
(user_id, location, access_time)
         │
1. Извличане на характеристики
   (същите като при обучението)
         │
2. model.predict([features])
      → 0 (Нормален)
      → 1 (Подозрителен)
         │
3. model.predict_proba([features])
      → проценти на увереност
         │
4. _generate_reason(features)
      → разбираемо за човек обяснение
         │
5. Връща:
   {
     classification,
     confidence_normal,
     confidence_suspicious,
     reason,
     ...
   }
```

---

## Нива на увереност (Confidence Scores)

Моделът връща два процента на увереност, които винаги дават приблизително 100% общо:

* **Confidence Normal** — колко сигурен е моделът, че поведението е нормално
* **Confidence Suspicious** — колко сигурен е моделът, че поведението е подозрително

Тези стойности се извличат от:

```python
predict_proba()
```

което връща разпределението на вероятностите между двата класа.

Пример:

```python
[0.87, 0.13]
```

означава:

* 87% Нормално
* 13% Подозрително

# Система от събития (Observer Pattern)

## Как работи

### 1. Регистрация

Слушателите се абонират за събития чрез:

```python
register_listener(event_type, callback)
```

---

### 2. Изпращане

Когато възникне събитие:

```python
dispatch_event(event_type, event_args)
```

извиква всички регистрирани callback функции.

---

### 3. Известяване

Всеки callback получава обект `event_args`, съдържащ необходимите данни.

---

## Събитие → Слушател

| Събитие                  | Условие за задействане             | Основен слушател                                   | Вторично действие |
| ------------------------ | ---------------------------------- | -------------------------------------------------- | ----------------- |
| `on_suspicious_behavior` | AI класифицира като подозрително   | `SecurityManager.on_suspicious_behavior_handler()` | Запис във файл    |
| `on_access_denied`       | AccessController отказва достъп    | `SecurityManager.on_access_denied_handler()`       | Запис във файл    |
| `on_multiple_attempts`   | Над 3 неуспешни опита за 60 минути | `SecurityManager.on_multiple_attempts_handler()`   | Запис във файл    |

---

## Места в кода, където се изпращат събития

| Събитие                  | Къде се изпраща                                    | Причина                        |
| ------------------------ | -------------------------------------------------- | ------------------------------ |
| `on_suspicious_behavior` | `AccessController.request_access()` ред 48         | AI класификация = Подозрително |
| `on_access_denied`       | `AccessController.request_access()` ред 54         | AI решение → отказ             |
| `on_access_denied`       | `AccessController._process_request()` ред 121      | Резервно правило → отказ       |
| `on_multiple_attempts`   | `SecurityManager.monitor_failed_attempts()` ред 48 | Открити >3 неуспешни опита     |

---

## Свързване на компонентите (в `app.py`)

```python
dispatcher.register_listener(
    "on_suspicious_behavior",
    security_manager.on_suspicious_behavior_handler
)

dispatcher.register_listener(
    "on_access_denied",
    security_manager.on_access_denied_handler
)

dispatcher.register_listener(
    "on_multiple_attempts",
    security_manager.on_multiple_attempts_handler
)
```

Всяко събитие има точно **един слушател** (`SecurityManager`), но архитектурата позволява лесно добавяне на още слушатели.

За едно и също събитие могат да бъдат регистрирани множество callback функции.

```python
high_frequency = [

    for uid, cnt in user_counts.items()
    if cnt > threshold
```

# Обработка на изключения (Exception Handling)

Проектът използва `try/except` блокове във всички основни слоеве на архитектурата.

---

## Изключения по слоеве

| Слой            | Прихванати изключения                                                                    | Къде                                                                                    |
| --------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **Database**    | Различни (грешки при връзка и заявки)                                                    | `database_manager.py` — `get_access_logs()`, `execute_query()`, статистически методи    |
| **AI/ML**       | Различни (грешки в модела)                                                               | `analyzer.py` — `extract_features()`, `get_access_frequency()`, `train_from_database()` |
| **File I/O**    | `FileNotFoundError`, `json.JSONDecodeError`, `csv.Error`, `ValueError`                   | `file_manager.py` — `read_json()`, `read_csv()`, `backup_database()`                    |
| **Events**      | Няма изрични try/except блокове (callback функциите се обвиват при изпращане на събитие) | `event_dispatcher.py`                                                                   |
| **Controllers** | Няма изрични try/except блокове (разчита се на по-ниските слоеве)                        | `access_controller.py`, `security_manager.py`                                           |
| **Seed Data**   | `PermissionError`                                                                        | `seed_data.py` — изтриване на файл на базата данни                                      |

```python
try:
    # операция, която може да се провали
    result = risky_operation()
    return result

except SpecificException as e:
    # обработка на грешката
    # връщане на резервна стойност
    return default_fallback_value
```
